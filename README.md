# 출석인정허가원 자동생성

학생 정보/수강 시간표를 DB에서 불러와 신구대학교 출석인정허가원(.hwpx) 서식에
자동으로 채워 넣고 다운로드하는 웹앱입니다. 원본 한글 서식의 디자인/서식은
전혀 건드리지 않고, 표 안의 빈 칸에 내용만 채워 넣습니다.

## 실행 방법 (로컬)

DB는 SQLite가 아니라 **PostgreSQL**을 씁니다 (아래 "무료 DB 연동하기" 참고).
아직 DB가 없다면 그 섹션을 먼저 보고 `DATABASE_URL`부터 만들어두세요.

```bash
pip install -r requirements.txt
cp .env.example .env         # DATABASE_URL을 본인 Postgres 연결 문자열로 수정
python -m app.seed           # 데모용 소량 샘플 데이터 (실제 데이터는 아래 참고)
python -m flask --app app.app run
```

브라우저에서 http://127.0.0.1:5000 접속 → 학번/이름으로 학생 검색·선택 →
결석 사유·기간·과목 선택 → "다음" → 과목별로 수업일과 시작/끝 교시 선택 →
"한글(.hwpx) 파일로 다운로드" 클릭. 상단 메뉴의 "사용 기록"에서 지금까지
생성된 허가원 이력을 확인·삭제할 수 있습니다.

## 무료 DB 연동하기 (Neon)

무료 Postgres 중에서는 **[Neon](https://neon.tech)**을 추천합니다.

| | Neon | Supabase | Render 무료 Postgres |
|---|---|---|---|
| 용량 | 0.5GB 무료 | 500MB 무료 | 1GB |
| 비활성 시 | 자동 슬립 후 요청 오면 몇 초 안에 자동 기상 | **7일 미사용 시 프로젝트 전체 일시정지** (대시보드에서 수동으로 다시 켜야 함) | - |
| 기간 제한 | 없음 | 없음 | **90일 후 DB 자체가 삭제됨** |

이 앱은 학생/교직원이 어쩌다 한 번씩 쓰는 용도라, 며칠씩 요청이 없을 수 있습니다.
Supabase는 그러다 프로젝트가 통째로 멈춰서 사람이 대시보드에 들어가 깨워야 하고,
Render 무료 DB는 아예 90일 뒤 삭제되기 때문에 이 용도엔 안 맞습니다. Neon은 접속이
뜸해도 자동으로 자고 깨어날 뿐 프로젝트가 삭제되거나 수동 개입이 필요하지 않아서
가장 무난합니다.

### 연동 순서

1. https://neon.tech 에서 무료로 가입합니다 (GitHub 계정으로 바로 가입 가능).
2. 새 프로젝트를 만들면 데이터베이스 이름(`neondb` 등)과 함께 **Connection string**을
   보여줍니다. `postgresql://사용자:비밀번호@ep-xxxx.region.aws.neon.tech/디비이름?sslmode=require`
   형태입니다. 이 문자열을 복사하세요.
3. 로컬에서 테스트하려면:
   ```bash
   cp .env.example .env
   ```
   `.env` 파일을 열어 `DATABASE_URL=`에 복사한 연결 문자열을 붙여넣습니다.
   (`.env`는 `.gitignore`에 있어서 git에 올라가지 않습니다.)
4. 스키마를 만들고 실제 데이터를 넣습니다:
   ```bash
   python -m app.import_real_data --roster ... --timetable 1:...
   ```
   (`import_real_data.py`가 내부에서 `init_db()`를 호출해서 테이블을 자동으로 만듭니다.
   따로 마이그레이션 도구는 없습니다 — 스키마가 바뀌면 `app/db.py`의 `SCHEMA`를 고치고
   다시 실행하면 됩니다.)
5. 나중에 호스팅 서버에 배포할 때도 **같은 `DATABASE_URL` 값**을 그 서비스의 환경변수로
   등록하면 로컬과 배포 서버가 같은 Neon DB를 보게 됩니다. Render/Railway 등은 보통
   대시보드에 "Environment Variables" 설정란이 있습니다.

## 실제 학사 데이터 넣기

**로컬 컴퓨터/Python 없이, 배포된 웹사이트에서 바로 업로드할 수 있습니다.**
배포 주소 뒤에 `/admin/import`를 붙여서 접속하세요 (예:
`https://attendance-permit-xxxx.onrender.com/admin/import`).

1. **관리자 토큰** 입력 — Render 환경변수로 등록해둔 `ADMIN_TOKEN` 값 (아래
   "웹에 배포하기" 참고)
2. **재학생명단**, **학년별 시간표** 파일을 각각 선택 (필요한 것만 골라서
   올려도 됩니다 — 예: 시간표만 새로 나왔으면 시간표 파일만)
3. **업로드 및 반영** 클릭 → 화면에 "학생 228명 적재 완료" 같은 결과가 뜹니다

파일은 서버 디스크에 저장되지 않고, 요청 안에서 바로 읽어서 DB에 반영한 뒤
버려집니다.

- **재학생명단**: 학과/학년/반별로 묶여 있는 전체 재학생 명단. 학번/이름/학과/
  학년/반만 저장하고, 파일에 있는 주민등록번호는 서식에 필요 없는 정보라 아예
  저장하지 않습니다. 이 파일을 올리면 같은 학기의 기존 학생 목록은 새 명단으로
  통째로 교체됩니다.
- **학과별 전체시간표** (학년별로 1개씩): 요일×교시 표에서 "분반 과목명 교수명
  건물 강의실" 형태의 셀을 파싱해서 과목명/담당교수/수업일/수업시간을 만듭니다.
  결석 과목 선택 목록과 서식에 들어가는 내용이 전부 이 파일에서 나옵니다 —
  강의계획서 파일은 시간표만으로 다 나오는 정보라 필요 없습니다.

매 학기 새로 받은 파일로 같은 화면에서 다시 올리면 됩니다. **학기** 입력란을
바꾸면 그 학기로 데이터가 들어가고, 웹사이트가 보여주는 학기는
`app/config.py`의 `TERM` 값이므로 학기가 바뀌면 그 값도 코드에서 같이
바꿔줘야 합니다.

터미널 사용이 익숙하다면 `python -m app.import_real_data --roster ... --timetable 1:...`
로 로컬에서 실행하는 것도 여전히 가능합니다 (완전히 동일한 로직을 커맨드라인
버전으로 감싼 것뿐입니다) — 두 방법 다 결과는 같습니다.

### ⚠️ 개인정보 취급 주의

재학생명단·시간표 원본 파일은 **절대 git에 커밋하지 마세요**
(`.gitignore`에 이미 제외 처리는 되어 있습니다) — `/admin/import`로 업로드하면
애초에 git과 무관하게 처리됩니다. 실제 이름·학번이 들어간 DB 자체도 git에
올라갈 일이 없습니다(로컬 파일이 아니라 Neon 같은 외부 Postgres에 있으니까요)
— 대신 `/admin/import`에 아무나 접근하지 못하도록 `ADMIN_TOKEN`을 충분히
길고 예측하기 어려운 값으로 정해두고, 그 값과 Neon 연결 문자열을 아는 사람을
잘 관리하는 게 중요합니다.

## 결석 교시 선택 + 과목당 누적 12시간 제한 + 사용 기록

허가원 작성은 세 단계입니다.

1. **학생 검색** (`/`) — 학번 또는 이름으로 검색해서 학생을 찾습니다 (전체
   명단을 보여주지 않고, 검색한 조건에 맞는 학생만 나옵니다).
2. **결석 사유·기간·과목 선택** (`/student/<id>`) — 시작일을 비워두면 자동으로
   오늘 날짜가 들어갑니다. 과목은 이번 학기 누적 12시간에 도달한 과목은
   자동으로 체크박스가 비활성화됩니다.
3. **결석 교시 선택** (`/student/<id>/review`) — 선택한 과목마다:
   - **수업일**: 결석 기간 안에서 그 과목이 실제로 열리는 날짜만 드롭다운으로
     골라 넣게 되어 있고 (예: "9/2 (수)"), 기본값은 결석 시작일에 가장 가까운
     날짜입니다. 이 값이 hwpx의 "수업일" 칸에 `8/31` 형식 그대로 들어갑니다.
   - **시작 교시 / 끝 교시**: 그 수업의 평소 교시가 기본으로 채워지지만,
     select box라 자유롭게 다른 교시로 바꿀 수 있습니다.
   - 과목별로 "이번 학기 누적 N시간, M시간까지 신청 가능"을 보여줘서 얼마나
     남았는지 바로 확인할 수 있습니다.

**과목당 누적 12시간 제한** — "1교시를 1시간으로 계산해서, 한 과목당 이번
학기 출석인정허가원 누적 사용 시간이 12시간 이상이면 더 이상 신청할 수
없음" 규칙입니다 (`app/config.py`의 `MAX_ABSENCE_PERIODS_PER_COURSE = 11`이
허용되는 최댓값). "누적"이므로 한 번에 다 안 써도 되고, 여러 번에 걸쳐
신청한 시간을 전부 더해서 판단합니다 — 예를 들어 이미 8시간을 썼다면
남은 3시간(11-8) 안에서만 다음 신청이 가능합니다. 다운로드 버튼을 누르면
서버가 이 합계를 다시 한번 계산해서 최종 확인합니다.

`permit_records` 테이블에 학생/과목/사유/결석 기간/수업일/시작·끝 교시를
전부 기록하고, `/records` 페이지에서 이력을 확인할 수 있습니다. 각 행 옆의
**삭제** 버튼으로 기록을 지울 수 있는데, 페이지 위쪽에 **관리자 토큰**
(`ADMIN_TOKEN`)을 입력해야 실제로 지워집니다 — 삭제하면 그만큼 그 과목의
누적 시간도 줄어듭니다. `/records` 조회 자체는 누구나 가능하고, 삭제만
토큰으로 막혀 있습니다.

## 웹에 배포하기 (무료 도메인/호스팅)

무료 서버는 **[Render](https://render.com)**를 기준으로 정리합니다 (GitHub 저장소를
그대로 연결해서 올리는 방식이라 제일 간단합니다). Flask 앱을 `gunicorn`으로 띄우는
`Procfile`과, Render가 저장소를 인식해서 설정을 거의 자동으로 채워주는
`render.yaml`을 이미 준비해뒀습니다.

계정 생성·결제·배포 버튼 클릭처럼 제가 대신 할 수 없는 부분(계정/자격 증명이
필요한 부분)과, 코드/설정 파일처럼 제가 미리 준비해둘 수 있는 부분이 나뉩니다.

이 앱은 **GitHub(코드) + Neon(DB) + Render(서버)** 세 가지만으로 완전히 웹
브라우저에서 운영할 수 있게 만들어져 있습니다. 로컬에 Python을 설치하거나
cmd를 쓸 필요가 없습니다 — 데이터를 넣는 것까지 전부 배포된 사이트 화면에서
합니다.

### 1단계 — Render 배포 + ADMIN_TOKEN 설정

**제가 이미 해둔 것**
- `render.yaml`, `Procfile` — Render가 저장소만 보고 서비스 설정을 자동으로
  채우도록 준비됨
- `/admin/import`, `/admin/seed` — 브라우저에서 xls 업로드/데모 데이터 적재를
  할 수 있는 관리자 화면 (아래에서 사용)
- 로컬 Postgres로 이 화면들과 실제 xls 업로드까지 전 과정 재검증 완료

**사용자가 할 일**
1. https://render.com 가입 (GitHub 계정으로 로그인하면 저장소 접근 권한도 같이 부여됨)
2. Render 대시보드에서 **New → Blueprint** 선택 → 이 GitHub 저장소 선택
   (`render.yaml`을 인식해서 서비스 설정이 자동으로 채워집니다)
3. 배포 설정 화면에 환경변수 두 개를 입력합니다:
   - `DATABASE_URL` — Neon 연결 문자열
   - `ADMIN_TOKEN` — 아무 문자열이나 직접 정해서 입력 (예:
     `sinku-attend-9f2k`처럼 남이 못 맞출 만한 값). 이후 `/admin/import`나
     `/admin/seed`에 들어갈 때 비밀번호처럼 씁니다. `render.yaml`에는
     `DATABASE_URL`만 등록돼 있어서 `ADMIN_TOKEN`은 화면에서 **"Add Environment
     Variable"** 같은 버튼으로 직접 하나 추가해야 할 수 있습니다.
4. 배포 시작 → 끝나면 `https://attendance-permit-xxxx.onrender.com` 같은
   무료 주소가 생깁니다.

### 2단계 — 데모 데이터로 연결 확인

배포된 주소 뒤에 `/admin/import`를 붙여서 접속하세요
(`https://attendance-permit-xxxx.onrender.com/admin/import`). 맨 아래
**"또는: 데모(더미) 데이터로 먼저 테스트"** 항목에 방금 정한 `ADMIN_TOKEN`을
입력하고 **"데모 데이터 넣기"** 클릭 → 학생 2명짜리 테스트 데이터가 Neon에
들어갑니다. 사이트 첫 화면(`/`)에서 그 학생들이 보이면, "코드 - Neon DB -
Render 서버 - 웹페이지"가 다 연결된 게 확인된 겁니다.

### 3단계 — 실제 데이터로 교체

같은 `/admin/import` 화면 위쪽에서 재학생명단/시간표 xls 파일을 선택해서
업로드하면 됩니다 (자세한 내용은 아래 "실제 학사 데이터 넣기"). 데모
데이터로 만들어졌던 학생 2명은 재학생명단을 올리는 순간 자동으로 지워지고
실제 명단으로 교체됩니다 (단, 데모용으로 만들어진 과목 2개는 학생처럼 자동
삭제되지 않으니, 신경 쓰이면 Neon 콘솔 SQL Editor에서
`DELETE FROM courses WHERE professor IN ('김철수','이영수');` 로 지워주세요).

### 도메인

무료 서브도메인(`*.onrender.com`)은 1단계에서 이미 확보됩니다. "완전 무료" 정식
도메인(.com/.kr 등)은 실질적으로 없다는 점은 미리 알아두시면 좋습니다 — 예전에
흔했던 Freenom(.tk/.ml) 무료 도메인은 더 이상 신규 발급이 안 되고, `eu.org`
같은 심사형 무료 도메인은 느리고 제한적입니다. 짧고 기억하기 쉬운 도메인이
꼭 필요하면 `.com` 기준 1년에 보통 1만원 내외로 구매(Namecheap, 가비아 등)하는
정도가 현실적인 선택지입니다. 도메인 결제는 제가 대신 할 수 없으니, 구매하시면
Render에 연결하는 것부터 같이 진행하겠습니다.

## 페이지 구성

상단 메뉴 3개가 사이트의 전부입니다.

- **허가원 작성** (`/`) — 학번/이름 검색 → 학생 선택(`/student/<id>`) →
  사유·기간·과목 선택 → 결석 교시 선택(`/student/<id>/review`) → .hwpx 다운로드
- **사용 기록** (`/records`) — 전체 이력 조회 + 관리자 토큰으로 개별 삭제
- **관리자 업로드** (`/admin/import`) — 재학생명단/시간표 xls 업로드,
  데모 데이터 적재(`/admin/seed`)도 이 페이지 안에 있습니다

## 구조

- `app/config.py` — 학기(`TERM`), 요일 순서, 과목당 누적 시간 제한, 교시 select 범위
- `app/db.py` — Postgres 연결(`DATABASE_URL`)과 스키마 (students, courses, course_slots, permit_records)
- `app/import_real_data.py` — 재학생명단/시간표 .xls 파싱 + DB 적재 로직
  (CLI(`python -m app.import_real_data`)와 `/admin/import` 웹 화면이 이 안의
  같은 함수를 공유합니다)
- `app/seed.py` — 소량 데모 데이터 (`/admin/seed` 웹 화면 또는 로컬 CLI에서 사용)
- `app/queries.py` — 학생별 수강 과목, 과목별 누적 사용 시간, 결석 기간 안에서
  유효한 수업일 목록 등 조회 헬퍼
- `app/hwpx_filler.py` — hwpx 템플릿을 열어 표 셀에 값을 채우고 다시 압축하는 핵심 로직
- `app/app.py` — Flask 라우트 (검색, 작성 폼, 결석 교시 선택, 생성+다운로드,
  사용 기록+삭제, `/admin/import`·`/admin/seed` 데이터 적재)
- `app/templates/`, `app/static/` — 화면
- `app/assets/attendance_permit_template.hwpx` — 학교 원본 서식 (수정 금지)
- `docs/hwpx-field-map.md` — hwpx 표 좌표와 필드 매핑 문서 (서식이 바뀌면 참고)
- `Procfile`, `render.yaml` — Render 배포 설정

## 속도에 대해

DB 조회는 학생 한 명의 과목 목록을 불러올 때 과목 수와 무관하게 항상 고정된
횟수(3번)만 Neon에 왕복하도록 짜여 있고 (과목마다 따로 물어보는 N+1 패턴이었던
걸 한 번에 묶어서 조회하는 방식으로 바꿈), 학생 검색창은 입력할 때마다
페이지 전체가 아니라 결과 목록(`#results`)만 fetch로 바꿔 끼웁니다
(`/students/search`).

다만 Render 무료 요금제는 15분 정도 요청이 없으면 서버가 완전히 잠들었다가
다음 요청에서 다시 깨어나는 데 30초 이상 걸릴 수 있고, Neon도 비슷하게 계속
쉬다가 깨어나는 데 시간이 걸립니다 — 이 "첫 요청이 느린" 현상은 코드로 없앨
수 있는 게 아니라 무료 요금제 자체의 특성입니다. 자주 쓰는 시간대라면 그 뒤
요청들은 빠릅니다.

## 알아둘 점 / 남은 일

- 결석 과목은 서식에 있는 빈 줄 수만큼(현재 7개)까지만 채울 수 있습니다.
- 시간표를 다시 업로드해도 같은 수업이 중복으로 쌓이지 않습니다
  (`course_slots`에 `(course_id, day, period_start, period_end)` 고유 제약을
  걸어뒀습니다) — 예전 버전에서 이미 중복이 쌓였더라도 다음 배포 때
  자동으로 정리됩니다.
- 지도교수/학과장 결재란은 실제 서명/날인용이라 자동으로 채우지 않습니다.
- 신청일자는 항상 오늘 날짜로 채워집니다.
- `/records` 조회는 누구나 볼 수 있습니다. 삭제 버튼은 `ADMIN_TOKEN`을 입력해야
  동작하지만, 조회 자체를 막고 싶다면 실제 서비스로 올리기 전에 별도 로그인을
  붙이는 걸 권장합니다.
- `ADMIN_TOKEN`을 Render에 설정하지 않으면 `/admin/import`·`/admin/seed`·
  `/records`의 삭제가 500 에러로 막힙니다 (의도된 동작입니다 — 토큰 없이
  실행되는 걸 막기 위함).
